# 讲稿生成可靠性改造方案

日期：2026-10-09。状态：用户已授权实施，正文优先链路已实现并在本机启用；实际验证和剩余边界见[实施记录](evidence/M2/draft-reliability-implementation.md)。下文保留实施前诊断及方案，不能把方案门槛当作正式验收已通过。关联 M2-F03/F04/F05/F06、FR05/FR06/FR07/FR11/FR18/FR19/FR20、NFR03/NFR05、AC02/AC11/AC12/AC16。使用 mooc-content-pipeline 方法。

## 结论

推荐采用“正文先保存、程序派生读法与字幕对应、教学核查独立执行”。讲稿正文接口不再要求模型返回复杂JSON；数据库和导出JSON由程序序列化。这样能消除主正文链路对模型JSON语法正确性的依赖。网络、限流、截断和内容质量仍可能失败，不能承诺所有制作永不失败。

上轮v6仍是有限提示纠错，不是此架构改造，单页成功不能证明长期稳定。

## 已核查问题

当前 `mooc_m2/service.py::generate_ai` 同时要求显示正文、独立读法正文、知识点、问题与来源、术语、待确认项、扩展解释和重复正文的sentence_pairs。一句话最多在同一答案出现四次，任何漏句、拼音或拼接差异都可能阻断整页。

当前配置为 `glm-4.1v-thinking-flash`。代码对视觉模型移除response_format，原因与[官方对话接口](https://docs.bigmodel.cn/api-reference/模型-api/对话补全)一致：该字段只用于文本模型。仅提示“必须JSON”不能替代接口支持的格式控制。

本轮只读检查Lecture 8历史逐次记录发现JSON格式错误19次、字幕对应错误9次、中文读法错误8次、来源错误1次；这是记录的请求尝试分类，不是独立页数或统计成功率。当前22/22页稿已保存、全局2个活动任务。未中断制作、重启服务、重跑课程或修改模型配置。

## 推荐链路

1. **课件理解**：保留原PPT结构、备注、原页图、来源页ID和相邻上下文。视觉模型用于原页图表/公式等信息理解，输出以有来源的资料候选保存；不把生成描述当作已核查事实，不以AI重画页替代原页。复用同一页/图/模型/提示版本命中的理解结果。
2. **正文生成**：文本模型输出当前页自然中文讲稿正文，不返回读法、句子配对、UUID或核查大对象。仅消费最终content，独立保存reasoning_content和原响应。来源页ID由本机已知输入绑定，不让模型复制长ID。检查非空、汉字、截断、拒答、输入回显与明显分析/格式杂质后立即持久保存正文候选；可疑回答继续拒绝，不能把所有返回字符串视为成功。
3. **本地派生**：以唯一显示正文为来源，先确定稳定句子及区间，再逐句应用已配置术语词典和确定性数字/单位规则，生成独立读法、控制事件及sentence_pairs。禁止把整个正文送给模型自由重写读法。已知规则例如`128GB→一百二十八吉字节`；百分数、区间、型号、缩写及公式分别处理，有歧义的写入pending并提供局部编辑。不能把所有数字用一个通用正则替换，不能删除括号、数组或引用。转换前后保留原文、规则版本、替换区间和来源；按真实TTS采样建立字幕时间。
4. **教学核查**：知识点、问题、答案、来源和扩展解释另行生成与保存，使用实际支持JSON模式的文本模型并做本地Schema/来源校验。[官方结构化输出说明](https://docs.bigmodel.cn/cn/guide/capabilities/struct-output)采用json_object加Schema验证，不能据此宣称支持服务端严格json_schema。核查失败只重做核查阶段，不重生成已保存正文；界面明确显示“教学核查待完成”，不能以空数组冒充核查已完成。正式审核/冻结仍要求全部数据和教师确认。现有完整未审核草稿规则可保留；实施时须在接口spec明确核查未完成状态如何显示及何时阻断正式路径。
5. **持久恢复**：逐页分别记录理解、正文、读法、核查的输入摘要、提供方、阶段状态、错误、请求计数与输出摘要。遇到页失败继续处理其余缺失页，最终汇总失败页；缺页整课不能发布成功。恢复只处理该页该阶段。保持有限请求预算、指数等待/抖动与明确next_retry_at；耗尽后暂停并提供可定位错误，不无限重试、不虚增进度。

所有本地JSON由程序构造及序列化；正文不再因未转义引号、代码围栏或多个JSON对象而成为“JSON解析失败”。正文内容异常仍必须被校验并明确定位。

## 模型与切换

不只替换当前视觉模型，也不通过增加max_tokens或取消校验来解决。候选文本服务必须单独验证中文教学质量、纯正文指令遵循、JSON模式（核查阶段）、限流与恢复，以及调用费用/授权。官方支持参数与真实端点探针均通过才记为可用；没有探针不能把配置字段当作已生效。当前免费/外传限制继续遵守，不自动启用付费模型或未经授权的其他提供方。

先用保存的真实响应和隔离项目验证新的正文/派生逻辑，再对难页进行真实候选对照；通过后只影响新任务，旧稿/人工稿/审核/失败和成片留存。旧任务消费已固定输入，不在运行中改变契约。实施需同步M2内容契约、一键流程和相关界面状态；本方案不直接修改这些生效契约。

## 建议验证门槛

- 回放JSON杂质、拼音、截断、漏句、错来源等保存响应：错误候选不会发布，正常正文不依赖模型JSON格式。
- 数字/单位/区间/数组/引用/公式专项；显示正文不变、逐句读法完整、控制事件偏移可复核，未知项明确pending。
- 至少3份不同课件，覆盖封面、结束、密集数字、公式、图表及仅图片页；分别重复运行，公布总页数、首次通过率、最终失败页及人工修订项。此为方案建议的工程评估，不是已冻结NFR指标。
- 断网、429、截断、服务重启和核查阶段失败后，只重做相应阶段；已保存正文摘要相同。
- 测试真实TTS与字幕完整性，不能以JSON/单元测试代替读法和教学质量评审。任一缺页/无效片段不会把整课标完成。

完成改造和以上验证前，不使用“以后绝不再失败”或“可靠性已通过”的表述。
