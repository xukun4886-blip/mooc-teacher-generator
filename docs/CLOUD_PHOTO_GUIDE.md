# 本机工作台调用云端 SadTalker：操作教程

适用日期：2026-10-09；项目 `D:\XuTao_Task`，指定服务器 `connect.westc.seetacloud.com:57089`。依据当前启动器、网页配置与[真实样片报告](evidence/M3/cloud-photo-real-benchmark.md)编写。没有重新生成课程或替教师确认质量。

## 1. 先理解三个地址

本机上传素材、准备讲稿和语音 → 通过 SSH 隧道发照片与当前驱动音频 → 云端 SadTalker 生成人物片段 → 下载回本机合成课程。

| 地址/端口 | 用途 | 在哪里填写 |
| --- | --- | --- |
| `connect.westc.seetacloud.com:57089` | SSH 登录与隧道 | Windows 终端启动命令 |
| `http://127.0.0.1:8787` | 隧道映射后的云端人物 API | 网页“API 地址” |
| `http://127.0.0.1:8765` | 本机课程工作台 | 浏览器，由启动器自动打开 |

云端 API 实际仅监听服务器自己的 `127.0.0.1:8787`。网页中的 `127.0.0.1` 则是你的电脑；隧道把它们接起来。因此网页不能填 SSH 地址或57089端口，也不需要对公网开放8787。

PPT、讲稿、参考音色处理、主任务数据库、审核、字幕和最终课程合成在本机。人物服务仅接收教师照片及逐页实际生成的驱动音频。照片云端配置不改变原视频/MuseTalk路径；现有讲稿服务的图文传输规则也不因此改变。

## 3. 确认云端服务运行

在 Windows PowerShell 输入：

```powershell
ssh -p 57089 root@connect.westc.seetacloud.com
```

提示密码时输入已有服务器密码，输入过程不显示字符是正常现象。当前主机已登记SSH主机密钥；若以后出现密钥变化，应核对服务器实际指纹，不直接删除验证记录。

登录后的终端是 Linux。先检查：

```bash
nvidia-smi
ss -lntp | grep ':8787'
```

部分服务器没有`ss`命令，可改用已部署环境检查端口：

```bash
/root/autodl-tmp/mooc-cloud/env/bin/python -c "import socket; s=socket.socket(); s.settimeout(3); print(s.connect_ex(('127.0.0.1', 8787))); s.close()"
```

输出0表示端口可连接；非0表示尚未连接成功，继续查看启动日志。端口可连接仍需网页完成带令牌的健康检查。

应看到GPU信息，以及仅绑定 `127.0.0.1:8787` 的服务。GPU利用率0%可以是空闲，也可以是CPU回贴阶段，不能单凭这一项判断模型出故障。

**只有8787没有监听时**，再启动已部署的API：

```bash
cd /root/autodl-tmp/mooc-cloud
nohup bash api-start.sh > "api-$(date +%Y%m%d-%H%M%S).log" 2>&1 < /dev/null &
```

随后再检查监听。需要看启动错误时，先 `ls -lt api-*.log`，再用 `tail -n 60 日志文件名` 查看最新文件。这里的“日志文件名”须替换为实际文件名。

这个脚本读入服务器私有令牌并启动单个模型工作进程；不要重复启动多个进程，也不要增加uvicorn workers。当前用的是后台启动，尚未配置开机自启；实例重启后需重新检查。不要打印或复制 `runtime.env` 的内容到网页或聊天。

退出这一登录窗口：

```bash
exit
```

后台API会继续运行。退出SSH登录不等于关闭GPU实例。

## 4. 在本机启动带令牌的工作台和隧道

### 首次准备独立的连接工具环境

以下命令在 **Windows PowerShell** 中执行，无需激活环境：

```powershell
Set-Location -LiteralPath 'D:\XuTao_Task'
.\.venv-m1\Scripts\python.exe -m venv .venv-cloud-admin
.\.venv-cloud-admin\Scripts\python.exe -m pip install paramiko
```

这是创建连接工具环境，不是重装SadTalker。后续已有 `.venv-cloud-admin` 和paramiko时跳过。若安装失败，保留具体错误排查；不要关闭TLS证书验证来绕过错误。

### 先处理已有监听，仅在全部任务空闲后操作

启动器不会接管已运行的8765服务。若已有工作台/隧道，先在它们原来的终端按 `Ctrl+C`；如果由后台启动，没有可关闭的终端，可查询：

```powershell
Get-NetTCPConnection -State Listen |
    Where-Object { $_.LocalPort -in @(8765,8787) } |
    Select-Object LocalAddress,LocalPort,OwningProcess
```

针对查出的每个PID核实命令行，下面的 `12345` 是示例，须换成实际PID：

```powershell
Get-CimInstance Win32_Process -Filter 'ProcessId=12345' |
    Select-Object ProcessId,ExecutablePath,CommandLine
```

仅当8765进程确实是本项目 `-m mooc_m2`、8787进程确实是本项目连接工具（`cloud_ssh_bridge.py`或此前临时管理工具`mooc_cloud_admin.py`），且任务均已结束，才停止对应PID：

```powershell
Stop-Process -Id 12345
```

不要结束全部Python进程。若还有其他不明程序占用端口，先核实它的用途。

### 正式启动

```powershell
Set-Location -LiteralPath 'D:\XuTao_Task'
.\.venv-cloud-admin\Scripts\python.exe tools/cloud_ssh_bridge.py --host connect.westc.seetacloud.com --port 57089 --workbench 'D:\XuTao_Task'
```

输入SSH密码后，成功时显示：

```text
SSH tunnel: http://127.0.0.1:8787 (private to this workstation)
```

启动器会读取云端私有令牌，仅注入新启动的本机工作台进程，然后打开浏览器。网页只填写环境变量名 `MOOC_CLOUD_TOKEN`，不要填写密码或令牌值。**这个PowerShell窗口要保持运行。** 它不负责启动云端API，所以第3节必须先完成。

需要重新打开已经启动的工作台时，在另一个PowerShell窗口执行：

```powershell
Set-Location -LiteralPath 'D:\XuTao_Task'
.\.venv-m1\Scripts\python.exe tools/m2_open.py --port 8765 --config config/m2.local.json
```

它用一次性登录票据打开页面，不显示持久密钥。普通 `tools/m2_start.ps1` 可以启动本机方案，但不会自动建立云端隧道或读入云端令牌；不能用普通启动代替上面的云端启动。

## 5. 网页怎么填写

1. 打开目标课程。已有课时在“高级设置 → 继续已有课程”中选择；新课程先上传教师**照片**、PPT和参考语音，等待素材处理完成。
2. 展开“高级设置 → 照片数字人处理”。不要在课程正在制作时修改处理位置。
3. “照片处理位置”选择“指定云服务器 SadTalker”。
4. 按下表填写，再点“检查连接与版本”。

| 网页字段 | 本次填写 | 含义 |
| --- | --- | --- |
| API 地址 | `http://127.0.0.1:8787` | 本机SSH隧道入口，不加 `/v1` |
| 令牌环境变量名 | `MOOC_CLOUD_TOKEN` | 变量名称，启动器提供实际值 |
| 渲染 batch | 先选 `1 · 基线` | batch2样片质量合格后再采用；本次batch4未更快 |
| 单片段时限 | `1800` | 单页人物计算允许等待30分钟，不是音频长度 |
| 允许照片和驱动音频外传 | 检查连接时可不勾；保存云端配置前勾选 | 当前课程的外传许可 |
| 允许服务器声明的计算费用 | 当前自建API保持不勾 | API声明费率为0 |
| 单片段费用上限 | `0` | API费用检查；云实例租金仍按平台账单 |

检查成功会显示“服务器配置就绪 · SadTalker”。“模型尚未加载”在刚启动API时正常：首次真实任务才加载；连续任务会复用常驻模型。“模型已常驻”表示已经加载，但不等于口型和人工质量通过。

**“检查连接与版本”不上传素材、不执行推理、不保存课程。** 若只是学习和检查连接，到这里就可以停止。

确定使用云端时，再点“保存照片处理设置”。摘要应显示“照片数字人处理 · 云服务器”，且无“尚未保存”。保存本身不生成整课；设置是按课程保存，新课程/换PPT不会自动继承云端许可，需要重新配置。

Lecture 9已有完整未审核草稿。切换处理位置会改变生成配置，旧草稿可能显示为修改前成果，但原文件、任务、失败和讲稿均保留。**再点“生成慕课视频”会进入整课制作，不是连接测试，也不是只做30秒样片。当前先评审样片，不用这个按钮试连接。**

## 7. 以后实际制作课程

完成样片质量评审并选定配置后，普通操作仍是：

**三项上传 → 保存本课程云端设置 → 一键完整未审核草稿 → 播放下载 → 教师主动确认。**

本机生成各页当前讲解语音，云端根据这份音频生成人物，片段返回本机后合成原PPT、字幕并检查整片。当前流程仍串行；尚未实现本机TTS和云端人物生成重叠。

电脑要保持开机、联网，避免休眠；本机负责调度、语音、下载与合成。浏览器关闭后本机后台进程可以继续运行，但隧道窗口必须保持。不要为看见“未响应”而反复点生成：人物长页计算、CPU回贴或编码时已完成页数可能暂时不变。

当前云端默认**单页驱动音频最多120秒**，与网页1800秒计算时限是两个概念。整课可以多页累计12分钟；某一页超过120秒须先评测并调整服务上限，不能靠删讲稿或误改超时来规避。

按现有小样片外推，12分钟课程媒体阶段约50–60分钟，未跑新整课验证；不包括PPT解析、讲稿准备、首次部署、排队或人工评审。不能保证点击按钮到成片就绪只需这个时间。

## 8. 断线、退出和回本机

断线时先恢复服务器/API/SSH隧道，再回网页查看同一个任务；明确失败且界面允许时使用“重试生成”。已有收据和兼容有效片段用于查询、续传和恢复，旧失败保留，不会用本机静态人物冒充云端成功。恢复能力有工程测试；真实推理中强制断线/重启演练仍待完成，不能保证所有中断都无损。

重启隧道如果8765仍在运行，不要再用 `--workbench` 启第二工作台。已由云端启动器启动、仍持有令牌的工作台，只需恢复隧道：

```powershell
Set-Location -LiteralPath 'D:\XuTao_Task'
.\.venv-cloud-admin\Scripts\python.exe tools/cloud_ssh_bridge.py --host connect.westc.seetacloud.com --port 57089
```

这个“仅隧道”命令不会给旧工作台补令牌；若网页仍提示令牌缺失，需等任务空闲后按第4节完整启动。

结束使用时，等任务完成并核查下载，隧道窗口按 `Ctrl+C`。**这只关闭隧道，不会关闭已启动的本机工作台、云端API或GPU实例。** 不再使用云端时，可在平台停止GPU实例；保留当前实例的数据盘和模型/任务目录，不选择删除实例或清盘。实例仍运行时，GPU空闲也可能计费。

下次想用原本机方案，在课程空闲时选择“本机 SadTalker（原有方案）”，再点“保存照片处理设置”。不删除云端配置历史、旧成果和缓存。若继续用云端，下次按第3–5节恢复连接，无需再次部署模型。

## 9. 常见问题

| 现象 | 应怎样处理 |
| --- | --- |
| `MOOC_CLOUD_TOKEN 尚未配置` | 当前工作台没有令牌。仅在PowerShell里设置变量不会改变已启动进程；任务结束后用带 `--workbench` 的云端启动器启动。 |
| `Local workbench is already running` | 8765已有工作台。不要重复启动；已持令牌时只恢复隧道，没有令牌时等空闲后关闭对应工作台再完整启动。 |
| 8787端口被占用 | 已有隧道或其他程序。查询PID/命令行；已有可用隧道不重复创建。 |
| `ModuleNotFoundError: paramiko` | 用第4节独立连接环境的Python执行；确认paramiko已安装在这个环境。 |
| SSH主机密钥未登记/认证失败 | 用第3节OpenSSH登录核实指纹、主机端口与密码；不要绕过主机密钥验证。 |
| 云端健康接口连接失败 | 按顺序检查实例开机、云端8787监听、本机隧道、网页地址。 |
| HTTP401 | 令牌不一致或请求未认证；用云端启动器提供令牌，通过网页检查；直接在浏览器打开受保护API并不等于有效检查。 |
| “模型尚未加载”但“配置就绪” | 正常懒加载；不用反复重启来预热。连接检查不加载模型。 |
| “服务器未就绪” | 按网页阻断原因排查依赖/CUDA/版本，不启动课程来试错。日志保留，必要时查云端最新API日志。 |
| 模型/实现版本改变 | 重新检查版本，在课程空闲时重新保存；质量评审重新核对，不能强行复用旧人物。 |
| “保存”按钮不可用 | 当前课程仍有素材处理或制作任务，等任务完成；不要关闭服务强行改配置。 |
| 长页进度看似不动 | 累计页数只统计完成页；看实际任务阶段、原生日志和GPU/CPU活动，不凭页数判断卡死。 |
| 超时或断线后失败 | 先恢复连接，再查看原任务并按界面允许的有限重试继续，不清库、不反复建新任务。 |

本机启动日志：`D:\XuTao_Task\storage\m2\cloud-bridge-workbench.log`。云端启动日志：`/root/autodl-tmp/mooc-cloud/api-*.log`；人物原生日志按云端任务保存在 `storage/jobs/` 下。排查时不要输出 `runtime.env` 或访问令牌。
