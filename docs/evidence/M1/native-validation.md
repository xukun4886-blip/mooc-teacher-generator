## 环境、资源与失败

三个模型使用独立 Python 3.10.4 环境，分别配 PyTorch 2.5.1/cu118、1.12.1/cu113、2.0.1/cu118；Windows CUDA wheel 和依赖安装已完成，pip check 通过。固定代码提交、全部主/辅助权重摘要及依赖冻结见 [模型环境](model-environments.json)，逐组件条件见 [使用记录](model-usage-local.md)。未修改固定上游已跟踪代码。

RTX 3050 Laptop 4096 MiB 串行运行：首批 TTS/照片/视频 PyTorch 峰值 allocated 约 1551/2317/2885 MiB，整卡采样峰值约 3055/3947/3655 MiB。整卡包括桌面及其他进程，allocated 不包含全部 CUDA 进程开销；不将二者混为“模型显存”。不据此承诺并发、长课稳定性或冻结性能指标。

MuseTalk 默认加载在转 FP16 前把完整精度 UNet 权重送入 GPU，实际发生 CUDA OOM（已有约 3.40 GiB 分配，追加 50 MiB 失败）。显式 cpu_staged_fp16 使用同一 UNet SHA-256，先 CPU 暂存、转 FP16，再送入 CUDA，成功生成；未更换模型、人物或视频模式。TTS 首次缺 matplotlib、离线语言资产未就绪引发下载停滞的真实失败也保留。后续明确补齐依赖、固定 fastText 模型，禁用回退及运行时下载。

TTS 单进程实测加载 2.78 秒，首次推理 25.38 秒，已加载引擎再次推理 14.30 秒，均输出真实 49.7 秒媒体。音频 B 取同一确认稿 TTS 的 10–40 秒，见 [音频 B](driver-b.json)。[照片 A/B 对照](photo-driver-comparison.json) 已真实完成：同一模型实例首次生成 635.73 秒，第二次 844.89 秒，预热未改善耗时；两片 750 帧均不相同，分别对应新驱动音轨，但帧差异也包含眨眼随机性，不能单独证明口型同步。

[视频 A/B 对照](video-driver-comparison.json) 也已真实完成，核心 VAE/UNet 加载约 10.83 秒（不含其他初始化）、首次全序列生成 437.64 秒、同一批模型再次生成 405.42 秒。各次直接提取当前音频，Mel/Whisper 特征摘要均不同；两份输出 900/900 帧不同，音轨分别与当前驱动波形相关（约 0.99759/0.99770）。保留原全序列并重新预处理，未复用第一段固定说话片。每次生成独立新媒体，不把旧片改音轨视为模型驱动验证。[资源与失败汇总](model-resource-readiness.json) 已更新，4 GB/Windows 本机基线不外推长课性能。
