`reset_peak_memory_stats`不会清空常驻CUDA分配器。星号的长页batch2是在batch4之后测量，reserved包含先前大batch留下的缓存，不代表它独立需要4804MiB；allocated是该次真实张量峰值。30秒首次batch2的reserved为2646MiB。原GPU4GB还承担桌面负载，不能用云端2.2GB allocated断言本机batch2稳妥，batch4已超过本机显存容量。当前云端32GB容量充裕，但未因此得到batch4更快的证据。

首次30秒上传0.988秒/下载0.500秒；82秒首次上传0.780秒/下载0.654秒，以[JSON](cloud-photo-benchmark.json)原始数值为准。后续相同输入blob命中，不再次传输其主体，但每个新operation仍重新推理。第一次照片预处理仅0.677秒，当前证据不支持把预处理缓存作为主要数倍提速来源。常驻省掉单次约9.75秒冷模型加载；冷/暖整体差还包含CPU和运行抖动，不能全归因于常驻。

82秒batch2中GPU渲染101.10秒、full回贴等53.18秒，其中seamlessClone47.23秒，小视频编码3.28秒，FFmpeg音轨mux合计0.77秒，云端输出完整检查1.18秒。full总计与clone/mux是嵌套计时，不能重复相加。剩余包含张量整理、数组转换、文件复制等混合工作；尚未独立测出纯磁盘读写、所有解码与编码CPU占用，不虚构精确占比，也未移除任何必要校验。

[真实重复查询](cloud-photo-cache-query.json)重新POST同一已完成幂等键：远端HTTP约0.011秒、任务数量6→6、不新增上传/推理。这只计远端localhost查询，不含SSH、结果下载和本机检查，不能作为生成速度。断线提交、Range续传、取消晚到发布和重启恢复由[工程专项](cloud-photo-specialized.xml)验证；本轮没有额外中断正在运行的真实模型样片，真实推理中断恢复仍需专项故障演练。

8份视频/音轨均完整解码、非异常静音、时长和全文件SHA检查通过，当前照片/驱动音频/模型绑定一致。每秒抽样的帧摘要均不重复，见[动态检查](cloud-photo-motion-check.json)，可以排除整段静态画面；第10秒帧也已查看。自然动作、身份保真、口型音素对齐、音色与长页后半段稳定性仍待教师视听评审，不能由摘要或完整解码证明。未代填确认，M1–M4仍未通过。[评审文件索引](cloud-photo-review-files.json)提供30秒/82秒batch2的原字节副本，没有额外编码，原输出保留；它们是原生人物片段，不是新整课成片，未单独声明浏览器播放通过。

## 推荐实施顺序和12分钟估算

1. 已完成：Web选择/只读检查、私有SSH接入、真实SadTalker、模型常驻、兼容照片预处理缓存、输入摘要、幂等收据和结果校验。可以保留这个可选接口继续评审，默认本机不变。
2. 先评审30秒与82秒batch1/2真实样片。当前batch2是优先候选：30秒较batch1快约1.37倍，82秒约1.30倍；batch4两种长度均未更快却显存更多。每条件只有一次，不把差值当显著性结论。质量合格后固定seed/资源条件，对batch2/4各做至少3次对照，再决定生产配置。默认仍为batch1。
3. 下一开发切片：本机TTS与远端人物生成有界重叠，继续用冻结输入、逐页持久状态和现有完整校验。首版仍逐页串行，重叠尚未实施，需失败/重启验证。原全新TTS估计16.37分钟，价值明显大于本机Sad加载合计约1.1分钟。
4. 后续样片诊断：独立测CPU回贴线程、数组整理、磁盘和重复解码；当前50秒左右的长页回贴是GPU继续提速的限制。先补计时再改编码路径，保持人物、讲稿、尺寸/帧率和发布校验。MuseTalk官方Avatar复用与其他照片模型继续按原方案独立评测，本轮未切换。

原本机成功恢复代127.70分钟为真实墙钟，包含少量兼容复用；全24页历史请求加混合余项约135.49分钟是全新媒体估计，仍不是全新整课实测。最新10.25分钟复用22页，不作为性能基线。本机保持现模型的小改动预估约120–135分钟，暂无小于1小时证据。

与本机同一第9页历史人物请求702.50秒相比，云端预热batch1/2/4完整接口分别约3.17/4.12/4.08倍。对当前串行媒体流程使用原全24页历史混合数据：

`T估计 = 16.37分钟语音 + 6.15分钟混合余项 + 112.96分钟历史人物请求 / S`

得到约58.14/49.96/50.24分钟。**目前合理的规划区间是约50–60分钟媒体阶段，属于小样本外推，不是整课实测或速度承诺。** 不含PPT解析、ASR/讲稿生成、第一次部署、长队列、异常恢复和教师评审；短页固定开销、vGPU共享与CPU波动会改变结果。按batch2候选有界重叠的理想下限约 `max(16.37,27.43)+6.15=33.58` 分钟加首尾/网络开销；调度未实现，不能承诺这个时间。

继续使用已有服务器即可，暂不采购。未来换规格时要求同输入、同源码/权重/full256/25fps/FP32/无增强、CPU/RAM/磁盘与资源份额明确，完整请求计时、峰值显存、传输和人工质量共同过关。8–12GB可以作为基于此次峰值的显存容量候选，16–24GB留更多余量；这些是容量推断，均未在其他GPU上实测，不能由VRAM推导计算速度。当前同模型主机RAM建议至少32GB并实测长页峰值。

平台费用无需成为本轮阻断项。API声明0费率仅表示此自建API不另按调用收费，实例租金仍依平台账单。每课费用方法为 `小时单价 ×（启动、推理、等待/空闲、失败恢复的实际计费秒数）/3600 + 存储/传输等费用`，部署耗时另行摊销。50–60分钟推算对应约0.83–1.00实例小时，仅在按课启停、无长空闲的假设下成立；没有平台价格就不填写实际金额。
