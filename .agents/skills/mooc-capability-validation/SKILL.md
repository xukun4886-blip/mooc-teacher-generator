# 数字人慕课能力验证

读取仓库根 [AGENTS.md](../../../AGENTS.md)、[M1 spec](../../../specs/M1-capability-validation.spec.md) 和 [项目状态](../../../docs/PROJECT_STATUS.md)，确定本次涉及的 M1 工作项。路径相对本 Skill 目录解析。

## 执行方法

1. 检查样例授权与输入摘要，记录实际设备、组件/权重版本和运行环境。候选模型名不构成已验证能力。
2. 分别验证原页渲染、TTS、照片人物和视频人物；各模型独立环境。优先形成最小真实 30 秒样片，再扩大输入。
3. 两条人物路径使用当前真实讲解音频。视频路径保留源序列动态；不能以抽帧照片或固定说话视频替代。
4. 适配器报告实际健康、能力、输出时长和错误；检查可解码性、非异常静音、音色/身份和口型。分别记录首次加载与预热、耗时和显存。
5. 缺配置、缺模型、输入不兼容和故障返回明确失败。预检仅检查条件，不为估算调用付费生成接口；无可靠基线标未知。
6. 把版本、样例摘要、命令/配置、媒体位置、人工检查及限制记录到阶段证据和项目状态；只有 spec 的全部退出条件满足才标 M1 通过。

硬件或权重缺失时可继续实现适配契约和独立检查，真实能力保持待验证。模拟测试仅验证接口，不得计作人物/音色实测。

模型版本更换时重跑受影响的能力及资源检查；中文或参考音色不兼容不能通过普通配音静默回退。使用条件无法确认时记录该候选尚不可采纳，并继续可独立完成的工作。
