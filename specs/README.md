# 数字人教师慕课生成系统阶段规格索引

本目录把 [需求文档 V1.1](../数字人教师慕课生成系统需求文档_V1.1.docx) 转为可执行的阶段功能规格。源文档要求、工程建议和待冻结参数在各 spec 中分别标明。当前 M1 真实课件、语音及照片/视频样片已生成，质量评审与退出验证待完成；阶段尚未通过，证据见 [项目状态](../docs/PROJECT_STATUS.md)。

## 阶段与执行入口

| 阶段 | 目标 | 核心退出成果 | 功能规格 |
| --- | --- | --- | --- |
| M1 | 验证真实模型和媒体链路 | 两条路径各 30 秒样片、中文及设备基线、能力表、失败预检 | [M1 spec](M1-capability-validation.spec.md) |
| M2 | 建立可审核的内容链路 | 10 页原课件映射、三种讲稿入口、逐页控制、对应试听音频 | [M2 spec](M2-content-pipeline.spec.md) |
| M3 | 完成可恢复的视频闭环 | 两条路径各约 3 分钟课程、四类成果、持久化任务、局部重做 | [M3 spec](M3-media-pipeline.spec.md) |
| M4 | 完成首版验收和交付 | AC01–AC18 记录、性能基线、教师评审、部署与操作资料 | [M4 spec](M4-acceptance.spec.md) |

协作方式见 [AGENTS.md](../AGENTS.md)。各阶段 Skill 由 AGENTS.md 路由；先读 spec 明确功能，再用 Skill 推进实施。

2026-10-08 用户决定重做主流程：三项输入 → 一键完整未审核草稿 → 播放下载 → 教师成片确认。见 [一键流程改造](ONE_CLICK_FLOW.md)。高级功能及正式验收门槛保留，不自动填写教师审核。

## 编号与状态

- `FR01–FR20`：源文档首版功能需求，全部 P0。
- `NFR01–NFR08`：源文档非功能要求。
- `AC01–AC18`：源文档验收用例；数值仍为建议目标，确认后冻结。
- `M1-F01` 等：本项目阶段工作项，细化原需求，不替代原需求编号。
- 追踪关系见 [TRACEABILITY.md](TRACEABILITY.md)，执行状态见 [PROJECT_STATUS.md](../docs/PROJECT_STATUS.md)。

工作项状态使用 `未开始`、`进行中`、`已实现待验证`、`已通过`、`受阻`。阶段退出只能使用实际证据；生成了 spec 不表示功能已完成。部分 AC 会在多个阶段逐步验证，M4 统一复验完整流程。

## 当前建议配置

| 配置 | V1.1 建议默认值或输入建议 | 实施说明 |
| --- | --- | --- |
| 照片 | JPG/JPEG/PNG；20 MB 上限；建议短边 ≥512 像素 | 短边建议与文件大小上限分开处理，不擅自把建议变成硬门槛 |
| 视频 | MP4，建议 H.264；500 MB 上限；片段 5–60 秒 | 检测实际可解码性，支持选取与预览 |
| 课件 | PPTX；1–50 页；100 MB 上限 | 旧 PPT 尝试转换，失败提示另存 PPTX |
| 参考语音 | WAV/MP3/M4A；50 MB 上限；建议 20–60 秒 | 实际模型最短时长由能力声明决定 |
| 正式成片 | 16:9；1080p；25 fps；H.264 + AAC | 1080p 指合成画布，不承诺人脸原生细节 |
| 预览 | 720p | 保持预览和正式成果身份可区分 |
| 单任务 | 建议不超过 30 分钟 | 超限提示压缩讲稿或拆课时，不强行大幅加速 |
| GPU 并行 | 初始一个 GPU 密集任务运行 | 其他任务排队；根据实测再调整 |

## 必须在实施中确定的决策

设备与显存、模型代码及权重版本、是否允许外部模型 API、数据库和工作队列、页面渲染器、字幕对齐器、访问控制方式、处理时限和存储策略。未决定事项记录在项目状态中；不能用虚构基线估算耗时或费用。

## 范围控制

首版包含原页还原、三种讲稿入口、两种人物路径、教学核查、严格失败处理和恢复能力。完整录音逐页对齐、多语言、批量生成、抠像、知识库、课程平台对接、教师素材档案、已完成片段提前预览、讲稿回写 PPT 属于 P1；学生提问驱动或分层讲解属于 P2。

改变阶段分配可以记录工程决策；改变 P0 范围或冻结指标须依据用户决定修订相关 spec 与追踪。不要以实现困难为由静默删减需求。
